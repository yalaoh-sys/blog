## 왜 직접 만드는가

분석 도구를 쓰면 편하지만, 쿠키 동의, 광고 차단, 데이터 소유 문제가 따라옵니다. 개인 블로그에서 필요한 것은 단순합니다. **글별 조회수, 어디서 왔는지, 사이트 안에서 어디로 이동했는지**입니다. 이 정도는 Firestore만으로 충분히 만들 수 있습니다. 다만 *잘못 설계하면* 방문이 늘 때 읽기 비용이 폭발합니다.

## 비용이 생기는 지점

Firestore는 문서 단위로 읽기와 쓰기에 비용이 청구됩니다. 방문 이벤트를 문서로 쌓고 대시보드가 그 문서를 모두 읽어 합산하면, 방문이 10만 건일 때 대시보드를 한 번 열 때마다 10만 번을 읽게 됩니다. 이 구조는 규모가 커질수록 나빠집니다.

해법은 **쓸 때 미리 더해 두는 것**입니다.

## 두 층으로 나눈 데이터 구조

```text
events/{eventId}              원시 이벤트 (90일 후 자동 삭제)
stats_daily/{yyyy-mm-dd}      그날의 집계 카운터
  └ posts / channels / paths / transitions 하위 컬렉션
sessions_daily/{날짜_세션ID}   UV 계산용 존재 확인 문서
```

방문 한 번이 들어오면 서버는 원시 이벤트를 저장하는 동시에, 그날의 집계 문서의 숫자를 `FieldValue.increment`로 올립니다. 이 연산은 동시에 여러 요청이 와도 서로 덮어쓰지 않고 안전하게 더해집니다.

대시보드는 **집계 문서만** 읽습니다. 30일치 통계를 보더라도 읽는 문서는 수십 개 수준입니다.

## 이벤트 설계: 무엇을 남기나

| 필드 | 용도 |
|---|---|
| sessionId | 익명 세션(브라우저 `sessionStorage`) |
| path, postId | 어떤 페이지, 어떤 글 |
| referrer, utm_* | 유입 경로와 캠페인 |
| channel | Direct, Search, Social, Referral, Internal, AI로 분류한 결과 |
| prevPath, seq | 세션 내 이동 순서 |
| device, browser, country | 기기·국가 분포 |

유입 경로는 referrer 도메인을 규칙으로 분류합니다. 검색엔진(Google, Naver 등), 소셜, 그리고 AI 서비스 도메인을 구분해 두면 **AI에서 온 방문**을 따로 볼 수 있습니다.

## 조회수 중복 방지와 UV

새로고침할 때마다 조회수가 오르면 숫자를 믿을 수 없습니다. 서버에서 `세션ID + 글ID` 키를 확인해, 같은 세션이 30분 안에 같은 글을 다시 열어도 한 번만 세도록 했습니다.

UV는 HyperLogLog 같은 복잡한 구조 대신 단순하게 갑니다. 그날 `sessions_daily`에 해당 세션 문서가 **없을 때만** 만들면서 UV를 1 올립니다. 정확한 사람 수는 아니지만 *세션 기준 방문자 수*로는 충분합니다.

## 이동경로 통계

페이지 A에서 B로 이동하면 `transitions` 하위 컬렉션의 `A→B` 카운터를 올립니다. 이것만 있으면 다음을 만들 수 있습니다.

- 랜딩 페이지 TOP(세션의 첫 페이지)
- 이탈 페이지 TOP(세션의 마지막 페이지)
- 가장 많이 일어나는 이동 TOP N 표

시각화는 처음에는 Sankey 차트보다 **이동 표**가 만들기 쉽고 읽기에도 충분합니다.

## 개인정보는 처음부터 줄인다

- IP 원문은 저장하지 않고, 하루 단위로 바뀌는 솔트를 섞은 해시만 사용합니다.
- 쿠키 대신 `sessionStorage`의 임의 ID를 쓰고 30분 비활동 시 종료합니다.
- 관리자 로그인 상태, 봇 User-Agent, 프리뷰 도메인은 집계에서 제외합니다.
- 푸터와 개인정보처리방침에 수집 사실을 알립니다.

## 한계도 알아둘 것

광고 차단기가 트래커 요청을 막으면 통계가 실제보다 적게 잡힙니다. 같은 도메인의 `/api/track`을 쓰면 차단 확률이 낮아지지만 0은 아닙니다. 이 한계는 대시보드에 *참고용 수치*라고 적어 두는 편이 솔직합니다.

## 요약

1. 쓰기 시점에 집계해서 읽기를 줄인다.
2. 원시 이벤트는 TTL로 자동 삭제한다.
3. 대시보드는 집계 문서만 읽는다.
4. 중복과 봇은 서버에서 거른다.
5. 개인정보는 수집하지 않는 쪽으로 설계한다.
